# Teacher courses, submissions, insights and student continuation

Routes: `/teacher/courses`, `/teacher/assignments`, `/teacher/insights`, `/learn`. The course header uses plain text navigation. Existing Web and Informatics content, quiz IDs/versions, group provisioning and exams remain unchanged.

Teachers create private courses, chapters and ordered lessons with plain text conspects, HTML slide presentations, answered questions, quizzes, video links and protected uploaded files. Drafts may be incomplete; publication validates all supplied material. Courses become visible only through explicit shares to the owner's actual roster groups, with only published lessons shown. Unsharing/draft changes revoke subsequent student reads and downloads. Other teachers have no access. The immutable admin allowlist can read all courses and group analytics but cannot edit another teacher's course. The admin's standard analytics page continues to report built-in lessons; custom-course results are available in group analytics.

Tasks bind to an existing built-in lesson or an owned, published custom lesson already shared with the chosen group. Student drafts are private. Up to five files can be attached; final submission locks editing. Teacher grading is 0–100 with feedback. Return-for-revision unlocks the draft and retains review history. Submitted-at time is stored and late submissions are labelled, not silently discarded. Text or a ready file is required to submit; pending uploads prevent finalization. Revision CAS prevents stale grade/editor overwrite. No notifications are sent.

Private R2 files use owner/scoped authorization on every download, raw streamed upload, declared/actual size checks, unique per-attempt object keys, retry/claim handling and deletion race cleanup. Documents/code are attachments with nosniff; only MP4/WebM teacher videos are inline with Range support. Uploads are capped at 20MB for documents/student files and100MB for teacher videos; the new learning area has500MB/500files per account. Future account/course deletion must clean R2 objects along with DB rows; no such delete endpoint is introduced here.

Insights use actual roster account IDs and college checks, never free-text group matching. Matrix colors show latest test percentage, not best and not an assertion of mastery. Unattempted and pending accounts are distinct from0%. First/latest/best/count and ordered history are retained. Error analysis uses at most the latest100 attempts with a compatible current quiz version; excluded versions are counted. Recommendations are deterministic and based on explicit test evidence, with limited-evidence/version caveats. Assignment grades are presented separately, not averaged into test scores. Admin can select other teachers' groups; regular teachers see only their own.

Student `/learn` combines accessible custom courses, latest built-in/custom lesson continuation, recent results and tasks/feedback. Built-in deep links validate registry IDs before opening a lesson. Root subject selection also offers accessible teacher courses. Activity opening is not treated as reading completion. No historical activity is fabricated.

Schema additions: schema-only migrations0006 and0007, appended snapshots. No existing user data migration/secret rotation. The course share mutation token keeps CAS and share replacement in one atomic D1 batch. Custom quizzes are server graded and replay-deduplicated, including concurrent requests. Built-in question metadata is generated separately in `analytics/question-details.json`; plain-text decoding does not change existing quiz hashes.

Checks: `node checks/learning.test.mjs`, `node checks/learning-client.test.cjs`, standard Sites build, and `node checks/auth-runtime.test.mjs` for real Worker+D1+R2 HTTP. The Node client checks exercise actual rendering and completion locking; they do not verify browser layout.
